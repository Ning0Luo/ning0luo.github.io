CPA security implies CPA security for multiple encryptions

One challenge ciphertext. Six slots to fill. The ladder is how you get from one to the other.

There are two attackers on this page and everything depends on keeping them apart. A is the one you hired: it breaks the t-message game, and you never see inside it. A′ is the one you build: it plays the ordinary one-message CPA game, and it runs A once inside itself as a subroutine. The trouble is that A′'s challenger deals it exactly one ciphertext while A demands t — so whatever A′ builds, its two worlds differ in a single slot, and A's vectors differ in all of them. The ladder is the only thing that spans that gap, and it charges a toll of t for the crossing.

The game A plays — multiple encryptions

PrivK^mult-cpa_{A,Π}(n): 1. k ← Gen(1ⁿ) 2. A, with oracle access to Enc_k(·), outputs two vectors M₀ = (m₀¹, …, m₀ᵗ) M₁ = (m₁¹, …, m₁ᵗ) with |m₀ʲ| = |m₁ʲ| for every j 3. b ← {0,1}; cʲ ← Enc_k(m_bʲ) for each j; A is given (c¹,…,cᵗ) 4. A keeps its oracle, outputs b′ 5. the experiment outputs 1 iff b′ = b A is PPT, so t = t(n) is polynomial. That is not a convenience — it is load-bearing. See below.

The game A′ plays — one message

PrivK^cpa_{A′,Π}(n): 1. k ← Gen(1ⁿ) 2. A′, with oracle access to Enc_k(·), outputs m₀, m₁ with |m₀| = |m₁| 3. b ← {0,1}; c ← Enc_k(m_b); A′ is given c 4. A′ keeps its oracle, outputs b′ 5. the experiment outputs 1 iff b′ = b One pair in. One ciphertext back. This is the entire budget your reduction has to work with.

The hybrids and the telescoping

H_i : ( Enc(m₁¹), …, Enc(m₁ⁱ), Enc(m₀^{i+1}), …, Enc(m₀ᵗ) ) H₀ = the challenge when b = 0 H_t = the challenge when b = 1 p_i := Pr[ A outputs 1 in H_i ] p_t − p₀ = Σ_{i=1..t} (p_i − p_{i−1}) ← telescoping Averaging: some single i has p_i − p_{i−1} ≥ (p_t − p₀)/t. You do not need to know which one. Picking i uniformly collects the average, which is exactly (p_t − p₀)/t.

Where the oracle is load-bearing

A′ has no key. It cannot produce Enc(m₁¹), …, Enc(m₁^{i−1}) or Enc(m₀^{i+1}), …, Enc(m₀ᵗ) out of thin air. Chosen-plaintext access is the only thing that lets one challenge ciphertext be dressed as a vector of t — and it is why this theorem is true for CPA and false for eavesdropping security.

The eavesdropping counterexample

Let Π be EAV-secure and deterministic — a one-time pad, say, or any scheme with Enc(k,·) a function. A submits M₀ = (m, m) M₁ = (m, m′), m ≠ m′ A outputs 0 iff c¹ = c² Pr[success] = 1. Single-message security gives nothing. Corollary: a CPA-secure scheme must be randomized (or stateful). Determinism dies at t = 2.

Why t must be polynomial

Each link is negligible. You are adding t of them. poly(n) · negl(n) = negl(n) ✓ 2ⁿ · negl(n) = anything at all ✗ Indistinguishability is not transitive for free. A chain of superpolynomially many individually-indistinguishable steps can have trivially distinguishable endpoints — walk one bit at a time from 0ⁿ to 1ⁿ and every step is a single flip. Polynomiality of t is what closes the argument.
